# Docs site

The documentation for the data-eng sandbox, built with [Astro](https://astro.build)
and [Starlight](https://starlight.astro.build), Astro's documentation theme.
It is published to GitHub Pages at
<https://ephraimhaber.github.io/data-eng-sandbox/>.

## Run it locally

Requires Node 22.23.4 or newer (Astro 7's minimum). `.nvmrc` pins Node 24, the version CI uses.

```sh
cd docs
npm ci
npm run dev        # http://localhost:4321/data-eng-sandbox/
```

| Command           | What it does                                                        |
| ----------------- | ------------------------------------------------------------------- |
| `npm run dev`     | Dev server with hot reload                                          |
| `npm run build`   | Production build to `dist/`. Fails on broken internal links         |
| `npm run preview` | Serves the built `dist/` the way GitHub Pages will                  |
| `npm run check`   | Type-checks `.astro`, `.ts` and content frontmatter                 |

## Where things live

```

├── public/favicon.svg
└── src/

    ├── content/docs/         one Markdown/MDX file per page
    │   ├── index.mdx         landing page (splash template)
    │   ├── start/            "Start here" (sidebar order set in config)

    │   └── reference/        autogenerated sidebar group
    ├── components/
    │   ├── Hero.astro        overrides Starlight's hero on the landing page

    ├── assets/core-mark.svg  logo in the header
    └── styles/theme.css      colour and type tokens
```

## Writing pages

- Add a `.md` or `.mdx` file under `src/content/docs/`. Its path becomes its URL:
  `pipeline/sync-job.md` is served at `/data-eng-sandbox/pipeline/sync-job/`.
- Every page needs `title` and `description` frontmatter.
- Files in `pipeline/`, `operations/` and `reference/` show up in the sidebar
  automatically. Set `sidebar: { order: 1 }` in frontmatter to change their order.
  `start/` is listed explicitly in `astro.config.mjs`.
- **Internal links must include the base path**, because the site lives at
  `/data-eng-sandbox/` on GitHub Pages:
  `[Start the stack](/data-eng-sandbox/start/quickstart/)`. The build fails
  on any link that doesn't resolve, including `#anchors`, so you can't
  publish a broken link.
- Starlight's components (`Aside`, `Tabs`, `Steps`, `FileTree`, `Code`, …)
  are available in `.mdx` files. Markdown can use `:::note`, `:::tip`,
  `:::caution` and `:::danger` asides directly.
- Images go in `src/assets/` and are referenced relatively, so Astro can
  optimise them.

The placeholder pages each list what they're meant to cover. Replace the
`:::note[Not written yet]` block when you write the page.

## Publishing to GitHub Pages

`.github/workflows/docs.yml` builds the site on every push to `main` that
touches `docs/`, and deploys it with the official
[`withastro/action`](https://github.com/withastro/action) and
`actions/deploy-pages`. Pull requests run the same type check and build, but
don't deploy.

**One-time setup:** in the repository's **Settings → Pages → Build and
deployment**, set **Source** to **GitHub Actions**.

### Custom domain

To serve from your own domain instead of `ephraimhaber.github.io/data-eng-sandbox`:

1. Configure DNS as described in [GitHub's custom domain guide](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site).
2. Add `public/CNAME` containing the domain, e.g. `docs.example.com`.
3. In `astro.config.mjs`, set `SITE` to `https://docs.example.com`, and remove
   `base`.
4. Remove the `/data-eng-sandbox` prefix from internal links.

## Design notes

The visual idea is an **ice core**. An Iceberg table builds up as a stack of
snapshots, one per ten-minute sync, the way a glacier lays down layers. The
landing-page illustration shows that: a thick initial-load band at the bottom,
thin incremental bands above, and one ochre "tephra" band. Ice-core scientists
use volcanic ash layers as dated markers. Here it's the snapshot you
time-travel to.

- **Colour:** cool blues taken from ice (`firn`, `glacier`, `meltwater`,
  `deep-core`), plus `tephra` ochre. Tephra only appears in the illustration and as the keyboard
  focus ring, so it always means "look here".
- **Type:** Archivo at an expanded width for headings, Atkinson Hyperlegible Next
  for body text (it keeps `l`, `1`, `I`, `0` and `O` distinct in identifiers),
  IBM Plex Mono for code. All fonts are self-hosted through Fontsource, so
  there are no third-party requests.
- **Motion:** one moment. On load, the newest band settles onto the core. It's
  disabled when the reader prefers reduced motion.

Tokens and their rationale are in `src/styles/theme.css`.
